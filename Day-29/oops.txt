2. Class
Definition

A class is a blueprint or template used to create objects.

It defines what data (attributes) and actions (methods) an object will have.

Real-time example — Mobile Application

Suppose we are developing Instagram.

We can create:

class User:
    username
    password
    followers

    login()
    logout()

Class = Design/Blueprint

Like a mobile phone design tells us what features a phone should have.

3. Object
Definition

An object is an instance of a class.

In simple words, the class is the blueprint, while the object is the actual thing created from that blueprint.

Example
class User:
    pass

user1 = User()
user2 = User()

Here:

User → Class
user1 → Object
user2 → Object

Object = Real thing created from blueprint

4. Encapsulation
Definition

Encapsulation means wrapping data and methods together inside a class and controlling access to the data.

The main purpose is data protection/security.

Real-time example — Instagram

Imagine Instagram stores:

username
password
email
phone number

The application should not allow everyone to directly access sensitive information such as the password.

So we can control access using:

Public
Protected
Private
Python example
class Instagram:
    def __init__(self):
        self.username = "Zaib"       # Public
        self._followers = 500        # Protected
        self.__password = "12345"    # Private
Meaning

Public

self.username

Can generally be accessed directly.

Protected

self._followers

Indicates that it should mainly be used within the class/subclasses.

Private

self.__password

Used to restrict direct access from outside the class.

Real-world idea

When you log into Instagram, you use your username and password, but you don't directly access Instagram's internal password storage.

So:

Encapsulation = Protecting and controlling access to data.

5. Inheritance
Definition

Inheritance allows a child class to acquire the properties and methods of an existing parent class and add new features to it.

Your Instagram example

Suppose Instagram had a version in 2020.

Instagram 2020
     ↓
Login
Post
Like
Comment
Message

Now Instagram in 2026 needs additional features:

Instagram 2026
     ↓
Login
Post
Like
Comment
Message
+
Reels
Stories
AI features
New security features

Instead of creating everything again from zero, the new version can reuse existing functionality and add new functionality.

Conceptually:

Instagram2020
      ↓
Instagram2026
      ↓
Existing features + New features
Python example
class Instagram2020:
    def post(self):
        print("Posting photo")

    def message(self):
        print("Sending message")


class Instagram2026(Instagram2020):
    def reels(self):
        print("Creating reels")

Now:

app = Instagram2026()

app.post()
app.message()
app.reels()

The Instagram2026 class gets the existing functionality from Instagram2020 and adds reels().

Important point

If we don't use inheritance, we may have to rewrite the old functionality, causing:

Code duplication
More development work
More chances of errors
Difficult maintenance

So:

Inheritance = Reuse existing code + Add new features.

6. Polymorphism
Definition

Polymorphism means "many forms."

It allows the same method/interface to perform different actions depending on the object.

Real-time example — YouTube

Imagine YouTube has different types of users/services:

YouTube
YouTube Premium

Both can perform:

play_video()

But the experience can be different.

Example
class YouTube:
    def play_video(self):
        print("Playing video with ads")


class YouTubePremium:
    def play_video(self):
        print("Playing video without ads")

Both classes have the same method:

play_video()

But they behave differently.

YouTube          → Video + Ads
YouTube Premium  → Video without Ads

This is polymorphism.

Easy way to remember

Same action/method → Different behavior

Other examples:

Payment → UPI / Card / Net Banking
Login   → Google / Facebook / Email
Vehicle → Car / Bike / Bus

The operation may be the same, but the implementation can differ.
